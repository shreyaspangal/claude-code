# Project instructions

@WORKFLOW.md

## Keeping WORKFLOW.md current

- `WORKFLOW.md` is the high-level map of the program. Read it before changing code.
- If a change alters the flow, message shape, env vars, or skill/argument rules, update the Mermaid diagrams and rules in `WORKFLOW.md` in the same change, along with its "Last updated" line.
- Tick off or add items under "Known gaps / next up" as they are done or found.
- Keep it high level: diagrams and short rules, not line-by-line code.

## Working style

- The user writes the core logic to learn the system. Explain the plan and why first, keep the scope minimal, and make changes one step at a time so each can be reviewed.
